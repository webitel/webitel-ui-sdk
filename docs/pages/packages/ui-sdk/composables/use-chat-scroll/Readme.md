# Композібли скролу чату

Набір із трьох композіблів, що керують поведінкою прокрутки в стрічці повідомлень чату:
`useChatScroll`, `useScrollToBottomBtn`, `useObserveHeightUntilStable`.

Живуть у бібліотеці `@webitel/ui-chats`. Споживаються як самою бібліотекою (`the-chat-container.vue`
— цільовий компонент, на який у майбутньому перейдуть усі чати), так і компонентами воркспейсу
(`current-chat.vue`, `the-chat-history.vue`). Логіка нетривіальна: більшість рішень тут —
відповідь на конкретні баги браузерного скролу й асинхронного завантаження контенту, тому
окремий розділ [«Підводні камені»](#підводні-камені-чому-саме-так) описує *чому* саме так, а не
лише *що* робить код.

---

## Загальна архітектура

Три композібли розв'язують різні задачі й складаються один в одного:

| Композібл                     | Відповідає за                                                                 |
| ----------------------------- | ---------------------------------------------------------------------------- |
| `useChatScroll`               | Ядро: stick-to-bottom, лічильник непрочитаних, пагінація вгору, mark-as-seen. |
| `useScrollToBottomBtn`        | Видимість кнопки «прокрутити вниз» і поріг її появи. Використовується всередині `useChatScroll`. |
| `useObserveHeightUntilStable` | Добиває скрол у потрібну позицію, поки контент асинхронно досаджується (хедер, медіа). Викликається окремо в компоненті поряд із `useChatScroll`. |

`useChatScroll` **уже містить** `useScrollToBottomBtn` — окремо його підключати не треба.
`useObserveHeightUntilStable`, навпаки, — незалежний інструмент; компонент створює його
інстанцію(-ї) сам і сам вирішує, за яким елементом стежити й з яким таймаутом.

---

## `useChatScroll`

Ядро скрол-системи. Тримає стрічку внизу, коли доречно; лічить непрочитані; відновлює позицію
після підвантаження старих повідомлень; повідомляє, що користувач побачив останні повідомлення.

### Input params

Обʼєкт параметрів `UseChatScrollOptions`:

| Params          | Type                                          | Description                                                                                          |
| --------------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `chatContainer` | `Ref<HTMLElement \| null>`                    | Скрол-контейнер (той, що має `overflow-y: auto`). За ним рахується позиція й вішається `useScroll`. |
| `chatContent`   | `Ref<HTMLElement \| null>`                    | Внутрішня обгортка з повідомленнями. За її ресайзом стежить `ResizeObserver` stick-to-bottom.       |
| `messages`      | `Ref<ChatMessageType[]> \| ComputedRef<...>`  | Масив повідомлень. Використовується для визначення нового повідомлення та «моє / не моє».           |
| `chatId`        | `ComputedRef<string>`                         | ID активного чату. Його зміна скидає стан скролу й переініціалізує спостереження.                    |
| `isChatClosed`  | `ComputedRef<boolean>`                        | Чи чат закритий. Для закритого чату stick-to-bottom **не** запускається (позицію задає компонент).  |
| `isLoading`     | `Ref<boolean> \| ComputedRef<boolean>` *(опц.)* | Прапорець підвантаження старих повідомлень. Коли він `true → false`, відновлюється позиція скролу.  |
| `onBeforeStart` | `(options: { scrollToBottom }) => void` *(опц.)* | Хук перед запуском спостереження при зміні чату. За замовчуванням просто скролить вниз.           |
| `onSeen`        | `() => void` *(опц.)*                          | Викликається, коли користувач біля низу й, отже, побачив останні повідомлення.                      |

### Return

| Params                  | Type                                     | Description                                                                                      |
| ----------------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `showScrollToBottomBtn` | `Ref<boolean>`                           | Чи показувати кнопку «вниз».                                                                     |
| `newUnseenMessagesCount`| `Ref<number>`                            | Скільки нових повідомлень прийшло, поки користувач не внизу. Для бейджа на кнопці.               |
| `scrollToBottom`        | `(behavior?: ScrollBehavior) => void`    | Програмно прокрутити до низу. За замовчуванням `'instant'`.                                       |
| `markSeenIfAtBottom`    | `() => void`                             | Ідемпотентно позначити чат переглянутим, якщо зараз біля низу. Можна викликати ззовні.           |
| `loadNextMessages`      | `(canLoadMore, onLoadNextMessages) => void` | Обгортка для пагінації вгору: ставить прапор завантаження й запамʼятовує верхнє повідомлення.  |
| `handleChatScroll`      | `() => void`                             | Обробник `@scroll`: оновлює видимість кнопки й перевіряє mark-as-seen.                            |

### Як працює

**Stick-to-bottom.** Основне завдання — тримати стрічку внизу, поки користувач читає свіже, але
не смикати її вниз, коли він гортає історію. Для цього `startStickToBottomObserving` вішає
`ResizeObserver` на `chatContent`. На кожну зміну висоти він рахує дві дельти — приросту висоти
(`heightDelta`) і зсуву `scrollTop` (`scrollTopDelta`) — і за ними вирішує, чи це нове
повідомлення знизу (тоді, за потреби, скролимо вниз), чи підвантаження історії згори (тоді
не чіпаємо). Деталі розрізнення — у [«Підводних каменях», п.2](#2-prepend-проти-append).

**Чому не `arrivedState.bottom`.** VueUse-івський `arrivedState.bottom` після програмного
`scrollTo` короткий час лишається `false`, хоча ми вже внизу. Тому «чи були ми біля низу»
рахується вручну (`wasNearBottom`, `isViewingBottom`) через відстань до низу з допуском
`bottomThreshold = 2` px (субпіксельне округлення). Див. [п.1](#1-arrivedstatebottom-лагає).

**Лічильник непрочитаних.** `newUnseenMessagesCount` росте не всередині `ResizeObserver`
(там він плутав нові повідомлення з підвантаженням історії), а у `watch(messages.length)` з
`flush: 'post'`. Приріст рівно на 1 — це одне нове повідомлення; приріст > 1 — пачка історії,
її ігноруємо.

**Mark-as-seen.** `markSeenIfAtBottom` — єдина ідемпотентна точка, що викликає `onSeen`. Рахує
позицію по живій геометрії, а не по `arrivedState.bottom` (той бреше на ремаунті з нульовою
геометрією). Викликається зі `scrollToBottom`, обробника скролу, вотчера `arrivedState.bottom`
і повертається назовні — щоб компонент міг смикнути його зі свого спостерігача. Див.
[п.6](#6-onseen-хибно-спрацьовував).

**Фуллскрин.** Композібл слухає `fullscreenchange` і на час переходу піднімає прапор
`isViewportTransition`, під яким stick-to-bottom пропускає тік. Це гасить паразитний скрол при
вході/виході з повноекранного відео (`WTEL-9968`). Аналогічний гард є і в
`useObserveHeightUntilStable` — див. [п.4](#4-паразитний-скрол-при-виході-з-фуллскрину).

**Відновлення позиції після пагінації.** Перед підвантаженням `getTopMessageEl` запамʼятовує
верхнє видиме повідомлення. Коли `isLoading` повертається в `false`, вотчер після `nextTick`
скролить назад до цього елемента, щоб стрічка не стрибнула.

**Скидання при зміні чату.** `watch(chatId)` скидає стан (`resetScrollState`), і для **не**
закритого чату після `nextTick` викликає `onBeforeStart` та запускає stick-to-bottom. Для
закритого чату спостереження не стартує — позицію задає сам компонент.

## `useScrollToBottomBtn`

Керує лише видимістю кнопки «прокрутити вниз» і порогом її появи. Окремо в компонентах зазвичай
не викликається — він усередині `useChatScroll`.

### Input params

| Params          | Type                             | Description                                                          |
| --------------- | -------------------------------- | ------------------------------------------------------------------- |
| `chatContainer` | `Ref<HTMLElement \| null>`       | Скрол-контейнер, за позицією якого визначається видимість кнопки.   |
| `arrivedState`  | `UseScrollReturn['arrivedState']`| Стан «прибуття» до країв від `useScroll` (використовується `.bottom`). |

### Return

| Params                             | Type                        | Description                                                        |
| ---------------------------------- | --------------------------- | ----------------------------------------------------------------- |
| `showScrollToBottomBtn`            | `Ref<boolean>`              | Чи показувати кнопку.                                              |
| `handleChatScroll`                 | `() => void`                | Перерахувати видимість кнопки (навісити на `@scroll`).            |
| `resetScrollToBottomBtn`          | `() => void`                | Примусово сховати кнопку.                                          |
| `updateScrollToBottomBtnVisibility`| `(el: HTMLElement) => void` | Перерахувати видимість для конкретного елемента.                  |
| `updateThreshold`                  | `(clientHeight: number) => void` | Перерахувати поріг появи від висоти контейнера.              |

### Як працює

Кнопка зʼявляється, коли відстань до низу перевищує поріг `threshold`. Поріг — це `max(136px,
30% висоти контейнера)`: 136px закриває кейс `WTEL-7136`, а 30% адаптує поріг під великі екрани.
Якщо `arrivedState.bottom === true` — кнопка ховається одразу, без перерахунку.

## `useObserveHeightUntilStable`

Добиває скрол у задану позицію, поки контент **асинхронно досаджується** — рендериться хедер,
довантажуються зображення/відео, і висота стрибає кількома хвилями. Викликає `callback` на кожну
зміну висоти `target` і зупиняється або за таймаутом, або на анмаунті.

> **Важливо про назву.** Після рефакторингу стоп іде за таймаутом/анмаунтом — жодної
> «стабілізації» тут немає. Назва лишилась з історичних причин. Це кандидат на перейменування —
> див. [«Відомі обмеження»](#відомі-обмеження--todo).

### Input params

| Params     | Type                       | Description                                                                                     |
| ---------- | -------------------------- | --------------------------------------------------------------------------------------------- |
| `target`   | `Ref<HTMLElement \| null>` | Елемент, за ресайзом якого стежимо (контейнер або контент — залежно від кейсу).                |
| `callback` | `() => void`               | Викликається на кожну зміну висоти `target` (окрім часу viewport-переходу фуллскрину).         |
| `timeout`  | `number` *(опц.)*          | Через скільки мс зупинити спостереження. **Якщо не передати — спостерігач живе до анмаунту.**  |

### Return

| Params        | Type         | Description                          |
| ------------- | ------------ | ------------------------------------ |
| `startObserve`| `() => void` | Запустити спостереження.             |
| `stopObserve` | `() => void` | Зупинити спостереження вручну.       |

### Як працює

`startObserve` вішає `ResizeObserver` на `target`; кожен тік викликає `callback`, якщо не
триває viewport-перехід фуллскрину (гард `isViewportTransition`, вікно 1000 мс). Якщо переданий
`timeout` — через нього `stopObserve` сам відключить спостерігача. На анмаунті все чиститься.

> **Практичне правило:** майже завжди передавайте `timeout`. Інстанція без таймауту живе до
> `onUnmounted` і може зловити ресайз тоді, коли скрол уже не треба чіпати — саме це давало баг
> із фуллскрином (див. [п.4](#4-паразитний-скрол-при-виході-з-фуллскрину)).

## Підводні камені (чому саме так)

Кожен пункт — це реальний баг, через який проходила ця система. Тримайте їх на увазі: більшість
пасток легко відкрити наново під час правок.

### 1. `arrivedState.bottom` лагає

**Симптом.** Після довантаження відео чат не доскролювався вниз, хоча користувач був унизу.
**Причина.** `arrivedState.bottom` від VueUse після програмного `scrollTo` короткий час читається
як `false`. На різкому стрибку висоти цього вікна вистачає, щоб пропустити автоскрол.
**Рішення.** Не покладатися на `arrivedState.bottom` як на єдине джерело правди. Відстань до низу
рахується вручну (`wasNearBottom`, `isViewingBottom`) з допуском `bottomThreshold = 2` px.

### 2. Prepend проти append

**Симптом.** При підвантаженні старих повідомлень згори стрічка стрибала вниз.
**Причина.** Браузерний scroll anchoring при вставленні контенту згори сам піднімає `scrollTop`
рівно на ту величину, на яку виросла висота. Через це «ми були біля низу» хибно проходило.
**Рішення.** Розрізняти prepend і append за збігом дельт:
`isPrepend = Math.abs(scrollTopDelta - heightDelta) <= bottomThreshold`. Prepend рухає `scrollTop`
на ту саму величину, що й висоту; ріст знизу лишає `scrollTop` на місці.
**Відкинутий варіант.** Ловити prepend за абсолютним розміром стрибка (`scrollTopJumped`) — дало
регресію на завантаженні відео (там `scrollTop` теж рухається синхронно зі `scrollToBottom`).
Правильний дискримінатор — саме збіг дельт, а не розмір стрибка.

### 3. Протухлий `prevScrollTop` на першій пагінації

**Симптом.** Стрибок вниз саме на *першій* підвантаженні історії; далі — норм.
**Причина.** `prevScrollTop` оновлюється лише всередині тіка `ResizeObserver`, а той тікає лише
на зміну висоти. Поки користувач гортає вгору, висота не змінюється → тіка немає → `prevScrollTop`
замерзає на стартовому значенні й до першої пагінації протухає. Дискримінатор із п.2 отримує
хибні вхідні дані. На наступних пагінаціях `prevScrollTop` уже свіжий (оновлений попереднім тіком),
тож баг тільки на першій.
**Статус.** Механізм відомий; баг відтворювався нестабільно. Тримайте на увазі при будь-яких
правках дискримінатора: він чутливий до свіжості `prevScrollTop`.

### 4. Паразитний скрол при виході з фуллскрину

**Симптом.** Вихід з повноекранного відео смикав стрічку вниз.
**Причина.** Інстанція `useObserveHeightUntilStable` **без таймауту** живе до анмаунту й при виході
з фуллскрину ловить ресайз уже після того, як погас гард `isViewportTransition` (вікно 1000 мс),
викликаючи зайвий `scrollToBottom`.
**Рішення.** Гард `fullscreenchange` усередині композібла **плюс** обовʼязковий `timeout` у виклику
(`WTEL-9968`). Гард гасить перехід, таймаут не дає спостерігачеві жити довше, ніж треба.

### 5. Автоскрол при закритті чату в постобробку

**Симптом.** Треба розрізняти «чат відкрили вже закритим» (скролимо) і «відкритий чат закрився в
постобробку на очах» (не скролимо).
**Рішення.** Знімок `wasClosedOnOpen` на момент відкриття (`WTEL-10003`). Колбек спостерігача
скролить лише коли `wasClosedOnOpen === true`.

### 6. `onSeen` хибно спрацьовував

**Симптом.** Чат позначався переглянутим без реального перегляду.
**Причина.** На ремаунті з нульовою геометрією (`clientHeight: 0`) `arrivedState.bottom` віддавав
застаріле `true`; короткі чати ніколи не переходили `false → true`, і вотчер не спрацьовував.
**Рішення.** Єдина ідемпотентна `markSeenIfAtBottom` на живій геометрії замість `arrivedState.bottom`
як джерела правди для seen.

## Приклади використання

### Базовий виклик `useChatScroll`

```js
const {
  showScrollToBottomBtn,
  newUnseenMessagesCount,
  scrollToBottom,
  handleChatScroll,
} = useChatScroll({
  chatContainer,
  chatContent,
  messages,
  chatId: computed(() => chat.value?.id),
  isChatClosed,
  onSeen: () => {
    if (chat.value?.id && isUnseen.value(chat.value)) {
      store.dispatch('features/chat/unseen/MARK_CHAT_SEEN', chat.value);
    }
  },
});
```

### `useObserveHeightUntilStable` поряд із `useChatScroll`

```js
const { startObserve } = useObserveHeightUntilStable(
  chatContainer,
  () => {
    if (isChatClosed.value) return;
    scrollToBottom('instant');
  },
  OBSERVER_TIMEOUT_MS, // завжди передавайте таймаут — див. п.4
);
```

### Реальні споживачі

- **`current-chat.vue`** — активний чат і закритий чат без контакту (пагінація через `offsetDate`,
  логіка `wasClosedOnOpen` для постобробки).
- **`the-chat-history.vue`** — контактний чат і закритий чат з якорем: тут **дві** інстанції
  `useObserveHeightUntilStable` — одна на хедер активного чату, друга (`WTEL-9997`) на якір
  закритого чату, бо контент росте асинхронно вже після першого скролу.
- **`the-chat-container.vue`** (`@webitel/ui-chats`) — єдиний бібліотечний компонент чату, на який
  у майбутньому **повністю перейдуть усі чати**. Скрол-пропси (`chatId`, `isChatClosed`, `messages`,
  `canLoadNextMessages`) прокидаються звідси вниз до контейнера повідомлень, де й живе скрол-логіка.

Перші два компоненти — найкраще джерело для розуміння різних сценаріїв: активний потік, закритий
чат зі скролом униз і закритий чат зі скролом до якоря. `the-chat-container.vue` — цільова точка
міграції, на яку варто орієнтуватися для нового коду.

## Відомі обмеження / TODO

Свідомі шорсткості, які варто вирішувати окремою задачею.

- **Назва `useObserveHeightUntilStable` не відображає суть.** Стоп іде за таймаутом/анмаунтом —
  жодної «stability» немає.
- **Логіка відновлення позиції при пагінації частково дублюється.** `loadNextMessages` /
  `getTopMessageEl` є і в композіблі, і подекуди перевписані вручну в компонентах
  (`current-chat.vue`, `the-chat-history.vue`). Кандидат на консолідацію в одному місці.
- **Крихкість `prevScrollTop` на першій пагінації** (п.3) — механізм відомий, але залишковий
  ризик є. Будь-які правки дискримінатора prepend/append варто перевіряти саме на першій
  підвантаженні історії.
