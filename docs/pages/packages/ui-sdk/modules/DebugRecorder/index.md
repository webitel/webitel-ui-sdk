# `DebugRecorder` Module

Самописець для дебагу на боці клієнта. Вмикається на час розслідування й пише
локально, в браузері користувача, все, що потрібно саппорту: HTTP, WebSocket,
SIP, WebRTC-статистику, стан мікрофона/гарнітури, помилки консолі, зависання
сторінки. На прохання саппорту користувач завантажує zip-архів і пересилає його.

Усі апки Webitel одного сайту пишуть в **одне** сховище, тож один архів показує
весь шлях користувача: авторизація → адмінка → флоу-діаграма, з переходами між
ними. Кожен запис знає свою апку, у звіті є фільтр по апці.

> [!IMPORTANT]
> За замовчуванням модуль **вимкнений** і нічого не пише. Вмикається на 24 години
> (перемикачем у налаштуваннях або параметром `?debug=1`) одразу для всіх апок,
> а паролі, токени, номери телефонів та e-mail прибираються **до** запису.

Чому саме так (а не Sentry/Faro, одне сховище на всі апки, хуки сесії):
[ADR 0002](https://github.com/webitel/webitel-ui-sdk/blob/main/docs/adr/0002-client-debug-recorder.md).

## Підключення

### 1. Файл, що імпортується першим

Самописець обгортає глобальні `WebSocket`, `RTCPeerConnection`, `fetch`, `XHR`,
`console`. Тому його треба встановити **до** того, як `webitel-sdk`/JsSIP
відкриють перше з'єднання.

```ts
// src/app/debug-recorder.ts
import { installDebugRecorder } from '@webitel/ui-sdk/modules/DebugRecorder';

installDebugRecorder({
  app: 'workspace', // коротке id апки: ним позначається кожен запис
  version: __APP_VERSION__,
});
```

```ts
// src/main.ts
// must stay the first import: wraps console/WebSocket/RTCPeerConnection before the SDK loads
import './app/debug-recorder';
import './app/css/main.scss';
// ...
```

> [!WARNING]
> Імпорт саме першим рядком. Якщо до нього встигне завантажитися код, що
> відкриває WebSocket, ці з'єднання самописець не побачить.

### 2. Logout і зміна користувача — нічого робити не треба

Робочі місця бувають спільними: наступний користувач не повинен отримати записи
попереднього. Модуль підписується на хуки сесії SDK (`@webitel/ui-sdk/scripts`:
`onBeforeLogout`, `onSessionUser`), які викликає стор `Userinfo`:

- `logoutUser()` перед виходом чекає, поки самописець видалить записи (не довше
  3 с, помилка хука вихід не ламає);
- `initialize()` повідомляє id користувача: якщо в браузері лежать записи
  **іншого** користувача (вийшов без logout, сесія протухла), вони видаляються, а
  запис вимикається. Запис триває (з чистого сховища), лише якщо його ввімкнули
  до входу вже після того, як попередній користувач зник, або ввімкнув сам новий
  користувач.
- Записи належать першому користувачу, що увійшов під час запису. Архів і
  статистику віддає лише йому: не до входу і не іншому користувачу. Поки записи
  нікому не належать (вхід не вдається), архів доступний одразу.
- Увімкнення з вимкненого стану (`?debug=1`, перемикач) починає з порожнього
  сховища: записи попереднього періоду не домішуються.

`wipeDebugRecorder()` лишився для апок, де вихід іде повз стор `Userinfo`.

### 3. `jszip`

Архів пакується через `jszip` (optional peer dependency `@webitel/ui-sdk`),
вантажиться лише в момент завантаження архіву. Якщо апка його не має:

```bash
npm i jszip
```

### 4. Перемикач у налаштуваннях (за бажанням)

Headless-composable для UI налаштувань; тексти й компоненти — апки:

```ts
import { useDebugRecorder } from '@webitel/ui-sdk/modules/DebugRecorder/composables';

const {
  available,    // самописець встановлено в цій апці
  recording,    // пише в цій вкладці
  enabledUntil, // коли вимкнеться сам (epoch ms) або null
  records,      // скільки подій у сховищі
  since,        // час найстарішої
  busy,
  setRecording, // (true) — вмикає для всіх апок і одразу пише тут; (false) — зупиняє й видаляє все
  download,
} = useDebugRecorder();
```

Увімкнення посеред роботи не бачить з'єднань, відкритих раніше (WebSocket, SIP):
варто підказати користувачу перезавантажити сторінку або відкрити потрібну апку.
Стан оновлюється сам (раз на 5 с і коли його змінює інша вкладка).

### 5. Vite (лише dev, за бажанням)

Production-збірка працює без налаштувань: воркер виноситься окремим чанком.

У dev на **Vite 7** pre-bundling не переписує шлях до воркера модуля, і
самописець тихо переходить на запис у головному потоці: усе пишеться, але без
детекції зависань. Щоб у dev було як у production:

```ts
// vite.config.ts
optimizeDeps: {
  exclude: ['@webitel/ui-sdk/modules/DebugRecorder'],
  include: ['jszip'], // CommonJS: без цього архів не збереться
},
```

На **Vite 8** нічого додавати не треба: там шлях переписується сам.

## Як користуватися (інструкція для саппорту)

| Дія | Як |
|---|---|
| Увімкнути | перемикач у *Налаштування → Загальні* (Admin, `/settings`), або відкрити будь-яку апку з `?debug=1` — коли до налаштувань не дістатися (білий екран, не працює вхід). Діє 24 год у всіх апках, переживає F5 і повторне відкриття |
| Видно, що пише | червоний чіп **● REC** у лівому нижньому куті; його меню — мовою апки (`localStorage.lang`, 9 мов) |
| Завантажити архів | клік на **● REC** → *Download archive*, або `Ctrl+Alt+Shift+D` |
| Зупинити й видалити | клік на **● REC** → *Stop and delete data…* → підтвердити, або вимкнути перемикач у налаштуваннях. Зупиняє запис в усіх відкритих вкладках |
| Вимкнути без видалення | відкрити з `?debug=0` |
| З консолі | `webitelDebug.download()`, `webitelDebug.disable()`, `await webitelDebug.stats()` |

Також запис зупиняється й видаляється на logout і коли входить інший користувач,
а сам вимикається через 24 год.

### Що в архіві

| Файл | Що всередині |
|---|---|
| `report.html` | почати звідси: зведення, завантаження сторінок по апках, «ймовірні проблеми», таймлайн із фільтрами (апка, канал, завантаження сторінки, текст); клік по рядку — повні дані. Працює офлайн |
| `timeline.txt` | той самий таймлайн текстом, проблеми зверху; у кожному рядку завантаження сторінки (`#N`) і апка |
| `sip.txt` | SIP-сигналізація повними повідомленнями |
| `events.ndjson` | усі події з усіма даними, для `jq`/`grep` |
| `stats.json` | обсяг по каналах, апках і типах подій |
| `manifest.json` | коли/де зроблено архів |

## Що записується

| Канал | Що |
|---|---|
| `http` | `fetch` і `XHR`: метод, URL (без секретних параметрів), статус, тривалість, тіло помилки (санітизоване) |
| `ws` / `sip` | кожен WebSocket: відкриття/закриття з кодом, кадри. Сокет із протоколом `sip` (JsSIP) пишеться як SIP |
| `webrtc` | стани `RTCPeerConnection`, ICE-помилки, `getStats()` кожні 5 с (RTP, обраний кандидат, кодеки) |
| `device` | дозволи мікрофона/камери, список пристроїв і зміни, кожен `getUserMedia`, mute/ended треків |
| `console` / `error` | `console.*`, необроблені помилки й rejections, CSP, помилки завантаження чанків |
| `lifecycle` / `perf` | online/offline, видимість вкладки, freeze/resume, довгі кадри ≥ 200 мс |
| `recorder` | зависання головного потоку (≥ 3 с), чи закрилось кожне попереднє завантаження сторінки нормально |

### Приватність

- Паролі, токени, `Authorization`, cookies, SIP `Authorization`/`Proxy-Authorization`,
  `user:password@` в URL прибираються за ключами й у тексті. URL з параметром,
  схожим на секрет, але нерозбірливим, цензурується повністю.
- SIP: імена в `From`/`To`/`P-Asserted-Identity`/… маскуються; у SDP прибираються
  `a=ice-pwd` і ключі SRTP (`a=crypto … inline:`), кодеки й кандидати лишаються.
  Тіло, що не є SDP (напр. SIP `MESSAGE`), замінюється типом і довжиною.
  Короткі внутрішні номери (`100`, `773`) не маскуються.
- Номери телефонів (9+ цифр) і e-mail маскуються, імена учасників дзвінка
  (`from`/`to`/`members`/…) — теж. Тексти чатів замінюються їхньою довжиною,
  змінні дзвінка — довжиною значень.
- Нічого не відправляється на сервер: дані лежать в IndexedDB браузера
  (кільцевий буфер, 100 000 подій, не старші за 48 год), поки користувач сам не
  завантажить архів.

## Як влаштовано

```
main thread                               Dedicated Worker
collectors ── sanitize ── RecorderSink ──▶ recorder-core ──▶ IndexedDB
(wrap WS/RTC/fetch/console)   батчі по 250 мс   heartbeat-watchdog   (ring buffer)
```

- Запис іде у воркер: якщо головний потік завис, воркер це помічає й пише
  `main-thread-stall-start`. Якщо воркер не стартував (CSP, старий браузер),
  та сама логіка працює на головному потоці, але без детекції зависань.
- Одне сховище на сайт: база IndexedDB `wt-debug` і ключі `wt-debug:*` у
  `localStorage`. Кілька вкладок і апок пишуть одночасно; кожне завантаження
  сторінки має свій `sid` і запис про себе з heartbeat.
- Чистий вихід позначається синхронно в `localStorage` на `pagehide` (окремо для
  кожного `sid`). Завантаження без такої позначки, що мовчить довше 15 с (фонова
  вкладка — 3 хв), наступна сторінка записує як «did NOT close normally»; живі
  сусідні вкладки не чіпаються.
- Власник записів (`wt-debug:owner`) — користувач, що першим увійшов під час
  запису; зміна користувача стирає записи.

## Обмеження

- Браузер не дає сторінці бачити remote IP:port HTTP-запитів, причини DNS/TLS
  помилок і справжні коди закриття WebSocket (майже завжди `1006`). IP медіа
  видно з WebRTC-статистики.
- Інший домен — інше сховище: Electron-застосунок і апки на окремих доменах
  збирають свій окремий архів.
- Вкладку, заморожену браузером у фоні довше 3 хв, буде записано як «did NOT
  close normally», навіть якщо згодом вона оживе.
- Самописець не стартує раніше, ніж завантажився JS апки: білий екран через
  помилку в `index.html` або в самому бандлі він не побачить.
